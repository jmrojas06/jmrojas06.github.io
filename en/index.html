Multimodal RAG: retrieval and fusion across modalities

An experimental study of how to retrieve and combine evidence from text, images, audio and tables in a RAG system, reporting results and limits without gloss.

See details

  • I found information leakage in my own baseline and fixed it. I added conflict detection and penalization across modalities.

Course challenge Artificial Intelligence course, 2026

Three-level memory and MCP servers for agents

A manager that gives an assistant memory at three levels, a RAG over PDF evaluated with RAGAS and two MCP servers to connect tools to an agent.

The evaluation is small: 5 questions over a single document.

See details
  • Three memory levels coordinated by a manager: short term (the last 10 messages), medium term (a session summary valid for 14 days) and long term (durable facts with importance, recency and a "right to be forgotten").
  • Short term: a window of 10 messages or 8,000 characters that evicts in pairs, so the user and assistant turns are never broken.
  • Medium term: a progressive session summary stored with a date in a vector database (Chroma). Only the last 14 days are retrieved and expired entries are purged.
  • Long term: the model extracts facts with an importance from 1 to 10. If a fact already exists it updates it instead of duplicating, and retrieval blends similarity (60%), importance (25%) and recency (15%, with decay).
  • RAG over PDF evaluated with RAGAS on 5 questions: faithfulness 1.00, context recall 1.00, context precision 0.90 and answer relevancy 0.89.
  • Two MCP servers in Python (FastMCP): one for notes with 3 tools and another that searches and reads the official LangChain documentation from its llms.txt index.

Research AI course experiment, 2026

Measured multi-agent architecture: is a team of agents worth it?

An agent system (orchestrator, parallel researchers, writer and critic) compared against a single agent with real models, measuring quality, cost, latency and coordination cost.

Starts from the course base notebooks, run with real models, fixed and documented.

See details
  • Two implementations of the same design: with LangGraph (a state graph) and from scratch with the OpenAI SDK over OpenRouter, to check the result does not depend on the framework.
  • 5 configurations, 8 questions times 3 repetitions (24 tasks each, about 1,000 calls) and a judge from a different model family to avoid bias. The whole experiment cost about 0.25 USD.
  • The single agent turned out 4 to 20 times cheaper and 2.5 to 6 times faster, with equal or better quality. Coordination takes 21% to 40% of the cost.
  • Optimizing (fewer subtasks and critic rounds, or a router) cut cost by about 30% without losing quality, but missed the 40% goal.
  • I measured the noise: the order between single agent and multi-agent flips between the two implementations, so I only call the differences in cost, latency and number of calls firm.

Winback: reactivation prediction and WhatsApp chatbot

A model that estimates the probability that a former member returns within 12 months, to decide whom to contact first, plus a chatbot that talks and hands off to an advisor anyone who wants to come back.

See details
  • A temporal split (the test set is looked at only once) and only pre-withdrawal features.
  • 12 models compared with bootstrap confidence intervals. I chose XGBoost for simplicity, because the ensembles tied within the error.
  • Shuffled labels to rule out leakage, probability calibration and an internal audit with 10 faults fixed.
  • Chatbot with rules for opt-out, complaint and advisor requests (no LLM calls); the model never sees the probability or health data. Sending is simulated, not tested with real WhatsApp.
